Independent audit result for PR #1020
Rejection ID: audit-rejection:483070ec-a291-41f1-ad47-2ad189d3adee
Verdict: REPROVADA

Finding A-001 — ALTO — canonical household-measure precedence inversion
The issue requires a safe persisted portion resolved through food_portions/convertFoodPortionToGrams to take precedence over a compatible static/local catalog portion. The audited implementation did the reverse: resolveStaticCatalogPortion returned before resolveStoredPortion. A discriminating example is a persisted bread portion of 45 g/unit versus static 50 g/unit; the contract requires the persisted result.

Finding A-002 — ALTO — governing precedence omitted from delivery specification/evidence
The normalized issue slice and standard evidence omitted the persisted-before-static precedence rule and therefore could stay green while validating the wrong priority. The regression test even asserted that the stored catalog search was not called when a static portion existed.

Required remediation
1. Resolve stored/persisted portion before the static catalog fallback.
2. Add a regression with deliberately divergent persisted and static values and require persisted to win, plus sibling cases.
3. Regenerate the canonical issue slice, requirement closure and evidence with the precedence invariant explicitly represented.
4. Because material code/tests change, rerun the exact-head gate and perform a new freeze/handoff before independent re-audit.
