Controle Calorias — correção do registro de ovo e melão

## Escopo
- A implementação deve partir da branch develop e a PR deve permanecer baseada em develop.
- A correção cobre o gate contável do WhatsApp e o motor nutricional usado pelo registro.

## Requisitos
- O sistema deve interpretar `1 ovo` como uma unidade canônica de 50 g sem solicitar peso ao usuário.
- O sistema deve interpretar `1 ovo frito` como uma unidade canônica de 50 g sem solicitar peso ao usuário, preservando o preparo no texto encaminhado ao motor nutricional.
- O sistema deve resolver `50 g de ovo frito` pela referência nutricional TACO de ovo frito, e não pelo perfil genérico de unidade nem pelo placeholder de inferência.
- O sistema deve resolver `185 g de melão dino` pela referência canônica de melão, sem usar o placeholder genérico, inclusive quando o extrator retornar `brand: Dino` para uma fruta classificada como natural.
- O sistema não pode remover uma marca comercial real nem aceitar silenciosamente `Dino` quando o alimento estiver explicitamente classificado como processado; esse caso deve permanecer fail-closed com clarificação de identidade.

## Controles obrigatórios
- Os testes devem executar o gate real e comprovar `50 g de ovo` e `50 g de ovo frito` sem chamada de clarificação.
- Os testes devem comprovar a composição frita e devem manter controles negativos para alimentos contáveis inseguros e para melão classificado como processado.
- A implementação deve preservar o texto do preparo e reutilizar o catálogo e os contratos nutricionais existentes, sem criar um segundo resolvedor paralelo.
